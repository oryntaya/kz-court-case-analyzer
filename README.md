# Анализатор судебных дел РК

Глобальный навык Claude Code: `~/.claude/skills/delo/`. Работает из любой папки, API-ключ не нужен.

## Установка

Исходники навыка лежат в папке `skill/`. Чтобы команда `/delo` заработала в Claude Code:

```bash
mkdir -p ~/.claude/skills && cp -r skill ~/.claude/skills/delo
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

В `skill/SKILL.md` указан путь к Python с библиотеками (`/Users/fv/Desktop/ai_analysis/.venv/bin/python`) —
при другом расположении проекта замените его на свой.

## Использование

```
/delo                                   — найдёт PDF/Word в текущей папке или попросит файл
/delo решение.pdf                       — анализ одного дела
/delo 1.pdf 2.pdf 3.pdf                 — несколько дел → ОДИН Word-файл
/delo решение.docx подробный            — подробный режим
```

Можно просто перетащить файлы в чат и написать «/delo».

## Результат

Один файл в `output/` (папка рядом с вашими файлами), оформленный по шаблону `template.docx`:
по каждому делу — фабула, истец, ответчик, решение суда, правовое обоснование, готовый устный ответ;
для нескольких дел — ещё сводная шпаргалка и вопросы для преподавателя.
Нормы сверяются с текстом документа; не найденные помечаются «⚠».

Дальше можно попросить: «скопируй результат», «сделай подробнее», «сделай короче».

## Важно
- Папку `ai_analysis` с `.venv` (pypdf, python-docx) не удалять — навык использует её Python.
- Шаблон лежит в `~/.claude/skills/delo/template.docx`; его оформление (заголовки, маркеры) копируется в результат.
- Сканы без текстового слоя не читаются (нет OCR); `.doc` — сохранить как `.docx`.

## Промпты

### Первый промпт (исходное ТЗ)

> **Промпт-ТЗ: Анализатор судебных дел**
>
> **1. Задача**
> Создать простой инструмент для анализа судебных дел Республики Казахстан. Инструмент должен автоматически изучать судебные акты и предоставлять краткий, структурированный анализ дела.
>
> **2. Контекст**
> Инструмент предназначен для студентов юридических специальностей. Пользователь загружает судебное решение или другие материалы дела, а система анализирует документ и выделяет:
> - Фабулу дела (краткое описание обстоятельств).
> - Истца и ответчика.
> - Требования истца.
> - Позиции сторон.
> - Решение суда.
> - Нормы законодательства, на которые опирался суд.
> - Краткий правовой вывод по делу.
>
> **3. Формат**
> Интерфейс должен быть простым и удобным. Основные элементы:
> - Поле для загрузки документа (PDF, Word).
> - Кнопка «Анализировать дело».
> - Кнопка «Скопировать результат».
> - Кнопка «Скачать анализ».
>
> Результат анализа должен отображаться в отдельных разделах с понятными заголовками. Пользователь должен иметь возможность получить как краткий, так и подробный анализ.
>
> **4. Пример**
> Пользователь загружает судебное решение по делу о взыскании задолженности. Инструмент должен определить:
> - Кто обратился в суд и к кому предъявлен иск.
> - В чём заключается спор.
> - Какие требования заявил истец.
> - Какие доказательства и аргументы представили стороны.
> - Какое решение принял суд.
> - Какие статьи законодательства Республики Казахстан применил суд.
>
> **5. Готово, когда**
> - Пользователь может загрузить судебный документ.
> - Система правильно определяет основные обстоятельства дела и стороны.
> - Выделяет требования истца и решение суда.
> - Указывает соответствующие нормы законодательства.
> - Формирует понятный и структурированный анализ.
> - Не придумывает отсутствующие в документе факты и статьи закона.
> - Результат можно скопировать или скачать.

### Финальный промпт (по которому получился готовый инструмент)

> Создай **глобальный навык Claude Code `/delo`** (папка `~/.claude/skills/delo/`) для анализа судебных актов Республики Казахстан для студентов-юристов. API-ключа нет, веб-приложение не нужно: анализ делает сама сессия Claude Code, а Python-скрипт только извлекает текст и собирает документ. Python — из `.venv` проекта (`pypdf`, `python-docx`).
>
> **Вход.** Один или несколько файлов PDF / .docx / .txt: пути в аргументах (в кавычках, с пробелами, перетащенные в чат), либо текст дела, вставленный в чат. Без аргументов — взять единственный PDF/Word из текущей папки; если файлов несколько — показать список и спросить номер; если нет ни одного — попросить файл. Слово «подробный» включает подробный режим, иначе стандартный (объём как в шаблоне).
>
> **Шаги.**
> 1. Скрипт `court_tools.py extract` извлекает текст каждого дела в `work/case_N/source.txt`. PDF часто отдаёт текст «по слову на строку» — склеивать в сплошной текст с разрывами перед разделами «ОПИСАТЕЛЬНАЯ / МОТИВИРОВОЧНАЯ / РЕЗОЛЮТИВНАЯ ЧАСТЬ». Сканы без текста — понятная ошибка (OCR нет), `.doc` не поддерживается.
> 2. Прочитать каждый `source.txt` целиком.
> 3. Для каждого дела записать `analysis.json`: `topic`, `short_name`, `court`, `case_number`, `decision_date`, `document_type`, `fabula`, `plaintiff {who, demands, grounds[]}`, `defendant {who, position}`, `third_parties`, `decision {intro, points[]}`, `norms[] {act, article, quote, explanation}`, `oral_answer[]`, `summary`, `warnings[]` (роли `plaintiff_label` / `defendant_label` — если в деле не «истец/ответчик»).
> 4. Если дел два и больше — записать `qa.json`: 3–6 вопросов преподавателю с ответами, **только** по нормам и выводам из загруженных дел.
> 5. Скрипт `court_tools.py build` собирает **ВСЕ дела в ОДИН Word-файл** (не по файлу на дело) на основе моего шаблона `template.docx` (копирует его стили, заголовки и маркеры). Структура: заголовок документа; по каждому делу — «Дело №N. Тема», строка с судом/номером/датой и разделы *1. Фабула дела · 2. Истец (кто, чего требует, почему считает права нарушенными) · 3. Ответчик (кто, позиция и доводы) · 4. Решение суда · 5. Правовое обоснование (норма: пояснение по тексту документа) · 6. Готовый устный ответ (1–2 минуты)*; в конце — «Сводная шпаргалка: Главная суть по каждому делу» и «Блок вопросов и ответов для преподавателя».
> 6. Каждую норму сверять с текстом документа (дословная цитата или номер статьи); не найденные помечать «⚠ не найдена в тексте документа — проверьте» и перепроверять до сборки.
> 7. В чате: для одного дела показать результат; для нескольких — список «Дело №N — тема — главная суть» и путь к файлу. Предложить «скопировать результат» (буфер обмена macOS), «подробнее», «короче».
> 8. После сборки удалить рабочую папку `work/` — остаётся только итоговый файл в `output/`.
>
> **Жёсткие правила.** Только факты из документа: ничего не домысливать, не добавлять статьи «из общих знаний». Чего нет — ровно «Не указано в документе». Нормы — только те, на которые документ ссылается прямо, с дословной цитатой. Суммы, даты, номера — точно; имена, скрытые звёздочками, не восстанавливать («ФИО скрыто в документе»). Противоречия и опечатки документа — в «Примечания», не исправлять молча. Связанные дела (решение → апелляция → кассация) отмечать. Язык — русский, понятный студенту.
>
> **Готово, когда:** `/delo файл1.pdf файл2.pdf …` выдаёт один .docx по моему шаблону; стороны, требования, решение и нормы определены верно; выдуманных фактов и статей нет (проверка норм не находит расхождений); результат можно скопировать и скачать; в проекте нет лишнего мусора.
