# Анализатор судебных дел РК

## Как определить, что анализировать

Вход: `$ARGUMENTS`. Не переспрашивай без нужды — действуй по первому подходящему пункту:

1. В аргументах есть один или несколько путей к файлам (в кавычках, с пробелами, перетащены в чат) → берём все. Слово «подробный»/«подробно» → режим подробный, иначе стандартный (как в шаблоне).
2. Аргументов нет, но пользователь вставил текст дела в чат → сохрани его в `work/case_1/source.txt` и пропусти шаг 1.
3. Аргументов нет → `ls` текущей папки: один PDF/.docx — берём; несколько — спроси номера (или «все»); ни одного — одной фразой попроси перетащить файл или указать путь.
4. Путь начинается с `~` — раскрой до `/Users/fv/...`. Не найден — скажи коротко и проверь похожие имена через `ls`.

Команды выполняй из текущей рабочей папки. Рабочие файлы — в `work/`, итог — ОДИН файл в `output/`. Python с библиотеками: `/Users/fv/Desktop/ai_analysis/.venv/bin/python` (папку не удалять). Скрипт: `/Users/fv/.claude/skills/delo/court_tools.py`. Оформление берётся из `/Users/fv/.claude/skills/delo/template.docx` (шаблон пользователя; структуру абзацев в нём не менять).

**Все дела — в один файл.** Никаких отдельных файлов на каждое дело.

## Шаги

1. **Извлечь текст** каждого дела (папки `work/case_1`, `work/case_2`, …):
   ```bash
   mkdir -p work/case_1 && /Users/fv/Desktop/ai_analysis/.venv/bin/python /Users/fv/.claude/skills/delo/court_tools.py extract "<файл>" work/case_1/source.txt
   ```
   При ошибке (скан без текста, .doc) — сообщи причину, остальные дела продолжай.

2. **Прочитать `source.txt` целиком** (Read; для длинного — по частям). Не пропускай части.

3. **Для каждого дела записать `work/case_N/analysis.json`** (Write) по схеме шаблона:
   ```json
   {
     "topic": "короткое название дела, как заголовок: «Восстановление на работе фельдшера»",
     "short_name": "2–3 слова для сводки (например «Фельдшер»)",
     "court": "суд", "case_number": "", "decision_date": "", "document_type": "решение / апелляция / кассация ...",
     "fabula": "фабула — обстоятельства дела связным текстом",
     "plaintiff_label": "Истец (необязательно: заявитель, подсудимый и т.п., если в деле иначе)",
     "defendant_label": "Ответчик (необязательно)",
     "plaintiff": {
       "who": "кто это (должность/статус, организация)",
       "demands": "чего требует",
       "grounds": ["почему считает права нарушенными — по пунктам"]
     },
     "defendant": {"who": "кто это", "position": "позиция и доводы"},
     "third_parties": "третьи лица/прокурор или 'Не указано в документе'",
     "decision": {"intro": "напр. «Суд первой инстанции удовлетворил иск частично:»", "points": ["каждый пункт решения; апелляцию/кассацию — отдельным пунктом, если в документе есть"]},
     "norms": [{"act": "акт", "article": "ст. N / п. N", "quote": "ДОСЛОВНЫЙ фрагмент документа (10–200 симв.) с этой ссылкой", "explanation": "что норма говорит и как применена — только по тексту документа"}],
     "oral_answer": ["абзацы готового устного ответа на 1–2 минуты (≈150–250 слов): о чём дело, позиции, решение суда и его основания"],
     "summary": "главная суть дела в 1–2 предложениях (для сводной шпаргалки)",
     "warnings": ["что в документе неполно/нечитаемо/противоречиво"]
   }
   ```

4. **Если дел два и больше — записать `work/qa.json`**: блок вопросов и ответов для преподавателя, 3–6 пунктов:
   ```json
   [{"q": "вопрос по нормам/выводам, которые встретились в делах", "a": "ответ со ссылкой на дело («Дело №N») и норму, как её применил суд"}]
   ```
   Ответы — только на основе загруженных документов, без выдуманных норм и фактов.

5. **Собрать один файл и проверить нормы**:
   ```bash
   /Users/fv/Desktop/ai_analysis/.venv/bin/python /Users/fv/.claude/skills/delo/court_tools.py build output/analiz_del.docx work/case_1 work/case_2 --qa work/qa.json
   ```
   (одно дело: `output/analiz_dela.docx` и без `--qa`). Скрипт сверяет каждую норму с текстом документа; не найденные помечает «⚠». При ⚠ — перепроверь по source.txt, исправь `analysis.json` (или убери выдуманную норму) и собери снова. Флаг `--title "…"` задаёт заголовок документа, `--copy` копирует в буфер, `--print` печатает Markdown.

6. **Показать результат.** Одно дело — покажи итог в чате (скрипт его печатает). Несколько дел — не выводи всё: дай список «Дело №N — тема — главная суть (1 строка)» и путь к файлу. Напомни сверять выводы с текстом акта и действующим законодательством. Предложи: «скопировать», «подробнее», «короче».

7. **Убрать за собой**: `rm -rf work` (должен остаться только файл в `output/`).

## Жёсткие правила содержания

- Только то, что есть в документе. Никаких фактов, сумм, дат, имён и статей «из общих знаний». Устный ответ и сводка — тоже только по делу.
- Чего нет в документе — ровно `"Не указано в документе"`.
- Нормы — только те, на которые документ ссылается прямо; название акта и номер статьи как в тексте; в `explanation` — то, что об этой норме сказано в документе. Каждая норма с дословной цитатой в `quote` (копируй из source.txt без правок).
- Роли сторон называй как в документе (истец/ответчик, заявитель, подсудимый, административный истец…).
- Суммы, даты, номера — точно. Имена, скрытые звёздочками, не восстанавливай — пиши «ФИО скрыто в документе».
- Если документы связаны (решение → апелляция → кассация), укажи это в `warnings` или `decision.points` и в сводке.
- Стандартный режим — объём как в шаблоне (фабула и позиции связным текстом, 3–8 норм, устный ответ ~1–2 мин). Подробный — больше фактов, расчётов, все нормы документа.
- Язык — русский, понятный студенту.
